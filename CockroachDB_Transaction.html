CockroachDB Deep Dive: Clocks & Distributed Transactions

A comprehensive architectural reference detailing Hybrid Logical Clocks (HLC) and distributed cross-range transaction mechanics in CockroachDB.

1. Hybrid Logical Clocks (HLC)

Hybrid Logical Clocks (HLC) solve a fundamental challenge in distributed systems: how to assign monotonically increasing timestamps that reflect real-world physical time without relying on specialized hardware like atomic clocks or GPS receivers (such as Google Spanner's TrueTime).

CockroachDB uses HLCs to enforce causality, determine transaction ordering, and achieve Serializable isolation across distributed nodes using commodity NTP clock synchronization.

The Core Problem HLC Solves

To preserve causality, a clock implementation must strictly satisfy the Causality Requirement:

$$\text{If Event } A \text{ happens before Event } B \quad (A \rightarrow B), \quad \text{then } L(A) < L(B)$$

Traditional clock mechanisms exhibit critical trade-offs:

  • Physical Clocks (NTP): Physical clocks inevitably drift. Node $A$ and Node $B$ can diverge by tens or hundreds of milliseconds. If Node $A$ executes a write at physical time $t=100$ and Node $B$ reads it immediately after, Node $B$'s physical clock might read $t=95$, triggering stale reads and causality violations.
  • Lamport / Vector Clocks: Logical clocks preserve causality ($A \rightarrow B \implies L(A) < L(B)$) but bear no correlation to wall-clock time. They cannot be queried for temporal ranges like "retrieve data written in the last 5 minutes."

HLC bridges both paradigms: It enforces causality like a Lamport clock while remaining tightly bounded to physical wall-clock time.

Anatomy of an HLC Timestamp

An HLC timestamp is structured as a two-part tuple: $(l, c)$:

  • $l$ (Physical Component): The highest physical timestamp observed by the node so far (expressed in milliseconds or nanoseconds).
  • $c$ (Logical Component): A logical counter used to order events that occur within the same physical tick.

Comparing two HLC timestamps $T_1 = (l_1, c_1)$ and $T_2 = (l_2, c_2)$ uses lexicographical evaluation:

$$T_1 < T_2 \iff (l_1 < l_2) \quad \text{OR} \quad (l_1 = l_2 \text{ AND } c_1 < c_2)$$
