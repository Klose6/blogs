Designing an Ads Click Aggregator

Event streaming At-least-once Real-time OLAP 10 min read

How do we ingest millions of ad clicks, reject duplicates, publish fresh campaign metrics, and still produce correct billable totals? This design separates the fast serving path from the source of truth.

On this page Requirements Estimation Architecture Write path Aggregation Storage Correctness Scaling Operations
01 / SCOPE

Start with the contract

The service accepts click events from ad-serving clients and exposes aggregated counts to advertisers. A click may arrive late, be retried, or be malicious. The reporting UI should be fast and fresh; billing should favor correctness over immediacy.

Functional

  • Ingest a uniquely identified click
  • Aggregate by campaign, ad, geography, and time
  • Query near-real-time metrics and historical reports
  • Filter duplicates, bots, and invalid campaigns

Non-functional

  • 99.99% ingestion availability
  • Metrics visible within 60 seconds
  • No accepted event silently lost
  • Auditable and replayable billing totals
Key design choice: “exactly once” is an end-to-end business property, not a message-broker checkbox. Use at-least-once delivery plus idempotent processing and periodic reconciliation.

Keep the request path short

202 Accepted
{ "event_id": "0199a3c8-...", "status": "queued" }
  1. Authenticate and rate-limit. Validate the publisher credential, request size, timestamp skew, and schema.
  2. Enrich minimally. Add server receipt time, coarse IP-derived geography, schema version, and trace ID.
  3. Append durably. Acknowledge only after the replicated event log confirms the write.
  4. Process asynchronously. Fraud checks and aggregation stay off the latency-sensitive request path.

Partition the log by a stable hash of campaign_id. This preserves per-campaign ordering while distributing traffic. Large campaigns can use a composite key such as campaign_id + shard_id.

05 / STREAM PROCESSING

Aggregate in event-time windows

A stateful stream job consumes clicks, performs initial fraud filtering, deduplicates by event_id, and maintains one-minute tumbling windows. Event time—not arrival time—keeps a delayed mobile click in the correct reporting period.

Late data policy: keep windows mutable for 10 minutes using watermarks. Events later than that are written to a correction stream and folded in by reconciliation.

Rollups

Write low-cardinality, mergeable rows rather than incrementing one database counter per click. Minute buckets can later roll up into hour and day buckets. 

aggregate key:
  (minute, campaign_id, ad_id, country, device, shard)

measures:
  click_count, valid_click_count, estimated_cost

merge:
  SUM(measures) grouped by requested dimensions

The extra shard dimension spreads hot campaigns across workers. Queries sum the shards, trading a small amount of read work for much better write distribution.

Use each store for one job

Enforce maximum time ranges and dimensions, pre-aggregate common views, cache completed historical periods, and return asynchronous export jobs for expensive reports.

07 / SEMANTICS

Design for retries and disagreement

Deduplication

Clients generate globally unique event IDs. The stream processor keeps a partitioned ID state with a TTL longer than the normal retry window. Database writes use deterministic bucket keys or idempotent upserts. A probabilistic filter can reduce lookups, but it must not be the only billing deduplicator because false positives would discard legitimate revenue events.

Replay

Stream jobs checkpoint offsets and state together. After a failure, processing resumes from the last checkpoint. For code bugs, start a new consumer from raw object storage, write to versioned aggregate tables, validate totals, then atomically switch the query layer.

Reconciliation

A daily batch recomputes closed periods from immutable raw events, compares results against stream aggregates, and emits adjustments. Dashboards are provisional; reconciled rows are marked final and become the source for invoices.

Optimize for availability

Collection accepts traffic during downstream degradation because the log absorbs pressure.

Never hide uncertainty

Expose freshness and finalization state so consumers know whether totals may still change.

08 / BOTTLENECKS

Scale by partition, then isolate skew

  • Ingest API: stateless instances behind regional load balancers; autoscale on request rate and queue latency.
  • Event log: add partitions for throughput, replicate across availability zones, and alert on consumer lag.
  • Stream state: use embedded state backed by durable checkpoints; rescale during low-traffic periods.
  • Hot campaigns: split one campaign across deterministic sub-shards and merge at query time.
  • OLAP: partition by date, distribute by campaign hash, and sort by common filter dimensions.
  • Regions: ingest locally and aggregate regionally; merge global reports asynchronously to avoid cross-region latency on every click.
Backpressure must propagate to the event log, not to users. If processing falls behind, autoscale consumers and degrade dashboard freshness while keeping click collection available.
09 / PRODUCTION

Observe business truth, not just servers

System signals

  • Ingest success and p99 latency
  • Partition throughput and consumer lag
  • Checkpoint duration and failures
  • Query latency and rejected queries

Data-quality signals

  • Duplicate and invalid-event rate
  • Late-event distribution
  • Raw-to-aggregate count delta
  • Spend anomalies by campaign

Define a freshness SLO: 99% of valid clicks appear in advertiser reports within 60 seconds. Track it using synthetic clicks that traverse the complete pipeline, not merely component health checks.

Final design summary

A durable log decouples ingestion from computation. Stateful stream processing creates fast, provisional aggregates. Immutable raw storage enables replay, audit, and correct billing. An OLAP store serves flexible reports, while idempotency and reconciliation make at-least-once infrastructure behave exactly once at the business level.
